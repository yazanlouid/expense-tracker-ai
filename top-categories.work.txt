1. WHAT WAS IMPLEMENTED
====================================================================

A new client-side route at /top-categories that ranks expense
categories by total spend for a selected time period.

Behaviour:

- Reads data through useExpenses() (localStorage, same single source of
  truth as the dashboard). Shows the same spinner as the dashboard while
  isLoaded is false.
- Period filter: reuses the existing PeriodSelector component and
  PERIOD_KEYS / PERIOD_LABELS, so all six existing periods are offered
  (This month, Last month, Last 3 months, Last 6 months, Year to date,
  All time) — a superset of the required This Month / Last 3 Months /
  All Time. Default is "thisMonth". The resolved range is printed under
  the period name via formatDate.
- Header summary card (3 tiles): Total spend (formatCurrency),
  Categories with activity, Transactions — all for the selected period.
- Ranked list (<ol>), descending by total. Each row shows:
    * 1-based rank in a slate pill (with a visually hidden "Rank" label)
    * CategoryBadge (emoji + category name, colour from CATEGORY_META)
    * total amount via formatCurrency
    * "N.N% of total"
    * a proportional bar whose width equals that same percentage
      (aria-hidden, colour from CATEGORY_META.color — never hardcoded)
    * "N transaction(s)"
- Empty state: when no expenses fall in the selected period the list is
  replaced by an explicit "No expenses in this period" panel; no broken
  or empty list is rendered.
- Zero-total safety: share is computed as `grandTotal > 0 ? total /
  grandTotal : 0`, so an all-zero-amount period yields 0% rather than
  NaN%. The bar width is 0 when the share is 0 and clamped to a 1%
  minimum only for non-zero shares.
- Accessibility: per CLAUDE.md, CATEGORY_META colours are not
  colourblind-safe (Entertainment #a855f7 vs Transportation #3b82f6 are
  near-identical under deuteranopia). Every row is direct-labelled with
  category name, amount, percentage and transaction count, and the
  coloured bar is aria-hidden, so colour never carries identity alone.
- "Back to dashboard" link in the page header (next/link to "/").
- Visual style matches the existing app: slate palette, `rounded-xl
  border border-slate-200 bg-white p-4 shadow-sm` cards, the same
  header shell as src/app/page.tsx.

Aggregation logic is pure and lives outside React in
src/lib/topCategories.ts:

- rankCategories(expenses): CategoryRanking[] — reuses
  spendingByCategory() and totalSpending() from analytics.ts, adds
  per-category transaction counts, 1-based ranks and shares. Categories
  with no expenses are omitted entirely. Ties are broken alphabetically
  so ordering is independent of input order.
- topCategoriesReport(expenses, period, reference = new Date()):
  TopCategoriesReport — resolves the period with the existing
  resolvePeriod() and slices with the existing expensesInRange().
  NO new date math was written; the local-midnight parseISO convention
  in analytics.ts is inherited rather than duplicated.

5. TESTING APPROACH AND ACTUAL VERIFICATION RESULTS
====================================================================

Approach: unit tests over the pure functions only, with a fixed
reference date `new Date(2026, 7, 13)` (local midnight, 13 Aug 2026) so
period boundaries are deterministic and match analytics' local-midnight
parsing.

Coverage (13 tests, 1 file):
  rankCategories
    1. orders categories by total spend descending, 1-based ranks
    2. counts transactions per category
    3. share = fraction of overall total; shares sum to 1
    4. omits categories with no activity
    5. empty input -> empty ranking
    6. all amounts 0 -> share 0, no NaN (zero-total case)
    7. alphabetical tie-break is input-order independent
  topCategoriesReport
    8. total / transactionCount / activeCategoryCount / ordering for a
       period, with out-of-period rows excluded
    9. thisMonth boundaries: 2026-08-01 (inclusive start) and
       2026-08-13 (inclusive end) counted; 2026-07-31 and 2026-08-14
       excluded; range === {start 2026-08-01, end 2026-08-13}
   10. last3Months boundaries: range === {2026-06-01, 2026-08-13};
       2026-05-31 excluded, 2026-06-01 included, 2026-08-14 excluded
   11. allTime spans min expense date to max, including future-dated
       expenses (2024-01-05 .. 2027-03-01)
   12. period with no expenses -> empty rankings, total 0, no division
       by zero
   13. no expenses at all -> empty report, degenerate range
